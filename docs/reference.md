# The .petra language

Generated by `python -m petra.teach --write` from the grammars the lowerers read, the registry and the
examples; do not edit. tests/test_teach.py fails when this file is stale. `petra docs reference` prints
this page. On the command line, `petra kinds [DOMAIN|KIND]`, `petra new KIND [--name NAME]` and
`petra registry list [PREFIX]` print the same tables.

## A file

```
petra 0

design "steel-shear-tab" {
  owner "s.engineer@example.org"
}

shear_tab st1 {
  basis lrfd
  ...
}
```

- The first line is `petra 0`, the language version.
- Then one `design` block, components, and `param`, `ambient`, `load`, `tests`, `claim` and `waive`
  declarations. Each component, load, tests, param and claim name is declared once.
- Inside a block, one attribute per line. A comment runs from `#` to the end of the line.
- A name is letters, digits and `_`, and starts with a letter or `_`. A `-` is never part of a name: write
  `L4x3-1/2x3/8` as `L4x3_1_2x3_8` and `WT5x22.5` as `WT5x22_5`.
- A registry id is dotted, `steel.A992`; the part after a dot may start with a digit, `bolt_group.120`.
  The registry list below gives every id, and the common names that stand for one.
- A number is exact: an integer, a decimal or a fraction `3/4`, never an exponent. Its unit follows it:
  `0.75 inch`, `45 kip`, `10mm`. A number with no unit is dimensionless.
- A string is `"..."`; `\"` and `\\` are its only escapes.
- A bound is a range with its provenance: `in [<lo>, <hi>] [mean <value>] signed "<owner>" source
  "<source>"`, or `measured` in place of `signed` for a measured value. Outside a family design every
  bound carries a signature. In a family, `param NAME` stands where a bound would.
- `in`, `mean`, `signed`, `measured`, `source` and `param` start a bound or a signature, so they are not
  names inside a line, and no declared name is a declaration word.

## Declarations

### design

One per file. `owner` is required; `environment` names a registry environment (the list below) and may be left out.

```
design "warren-footbridge-panel" {
  owner "a.reviewer@example.org"
  environment indoor_dry
}
```

### param

Declares a family: the design holds for every value in the range. An attribute line or a load names it as `param NAME` where a bound would go.

```
param run in [0 m, 20 m]
```

### ambient

The ambient temperature range, signed.

```
ambient in [10 degC, 40 degC] signed "site.manager@example.org" source "site survey 2026-09"
```

### component

`KIND NAME { ... }`, one attribute per line. The kinds and their lines are below.

```
demand hook {
  capacity in [36 kN, 40 kN] measured "qa.lab@example.org" source "proof-load report PL-0917"
}
```

### load

A load case: `on <target> <field> <bound>` entries, each signed by its own signature or by the block's last line. A probability claim reads a `mean`.

```
load lift {
  on hook force in [0 kN, 40 kN] mean 10 kN
  signed "ops.lead@example.org" source "hoist duty log 2025, 14200 lifts"
}
```

### tests

A record of proof tests, which a tested-failure claim reads.

```
tests proof {
  on hook trials 300 failures 0 at 36 kN
  signed "qa.lab@example.org" source "batch 2026-09 proof tests, independent lots"
}
```

### claim

Three forms: a bound on a quantity, with an optional margin and the load cases it holds under (every case on the component when `under` is left out); a range-and-mean probability bound; a tested-failure probability bound. The kinds below list each kind's quantities. A claim with a margin is MARGINAL when it is proved and a certified point lies within the margin of its bound.

```
claim strength: frame.collapse_factor >= 1.5 under crowd
claim stress:   frame.member(diag_ad).stress <= 235 MPa margin 10 MPa under crowd
claim overload: P(hook.utilisation > 1) <= 3/10 under lift
claim tested:   P(fail hook at 36 kN) <= 1/100 confidence 95 % from proof
```

### waive

Accepts an open coverage demand on a component: a failure mode (the kinds below list each domain's) and who answers for it. A waived demand is reported as waived, never as proved.

```
waive bolt.plate_bearing on bracket by "m.engineer@example.org" reason "bearing checked by test PB-3"
```

## Grammar

EBNF; NL is a line end. Component kinds and their lines are not in the grammar: each domain declares its own (below).

```
file      = "petra" INT NL { decl NL } EOF ;
decl      = design | param | ambient | load | tests | claim | waive | component ;
design    = "design" STRING "{" NL { ( "owner" STRING | "environment" IDENT ) NL } "}" ;
param     = "param" IDENT "in" range ;
ambient   = "ambient" bound ;
component = KIND IDENT "{" NL { attr NL } "}" ;    KIND: an IDENT not in DECLS
attr      = IDENT { arg } ;
arg       = bound | qty | tuple | ref | STRING | ":" | "--" | "->" ;
tuple     = "(" qty { "," qty } ")" ;
bound     = "in" range [ "mean" qty ] [ signature ] | "param" IDENT ;
signature = ( "signed" | "measured" ) STRING "source" STRING ;
load      = "load" IDENT "{" NL { "on" path IDENT bound NL } [ signature NL ] "}" ;
tests     = "tests" IDENT "{" NL "on" path "trials" INT "failures" INT "at" qty
            [ signature ] NL [ signature NL ] "}" ;
claim     = "claim" IDENT ":" ( qoi rel qty [ "margin" qty ] [ "under" IDENT { "," IDENT } ]
          | "P" "(" qoi ">" qty ")" "<=" NUMBER "under" IDENT
          | "P" "(" "fail" path "at" qty ")" "<=" NUMBER
            "confidence" qty "from" IDENT ) ;
waive     = "waive" ref "on" path "by" STRING "reason" STRING ;
range     = "[" qty "," qty "]" ;
qty       = NUMBER [ unit ] ;     an IDENT or "%" right after a NUMBER is its unit
qoi       = segment { "." segment } ;          last segment is the quantity name
segment   = IDENT [ "(" IDENT ")" ] ;          member(diag_ad) names element diag_ad
path      = IDENT { "." IDENT } ;
ref       = IDENT { "." IDENT } ;   a local name, a domain keyword, a registry id,
                                    a port (w1.b) or a failure-mode id
rel       = "<=" | ">=" ;
```

## Component kinds

A component is `KIND NAME { ... }`, one line per attribute. A required line appears at least once.
A `<length>` is a length, a signed bound or `param NAME`. Cross-domain modes, waivable on any component: `port.contract`, `corrosion.galvanic`.

### Domain truss

Waivable modes: `truss.compliance`, `truss.elastic_stress`, `truss.global_stability`, `truss.member_buckling`, `truss.plastic_collapse`.

#### truss

`truss <name> { ... }`. `petra new truss` prints `examples/truss_pass.petra`.

- load: `on <truss>.<node> fx|fy in [<lo>, <hi>] [mean <value>]`
- `claim <name>: <truss>.<qoi> <=|>= <value> [margin <value>] [under <load>, ...]`
- `<qoi>`: `collapse_factor`, `stability_factor`, `stress`, `compliance`, `buckling_utilisation`

| line | form | needed | unit | ids | meaning |
|---|---|---|---|---|---|
| `node` | `<name> at (<x>, <y>) [support pinned\|roller_x\|roller_y]` | required | length |  | a joint at exact coordinates, one line per node, y pointing up (the members' own weight acts in -y); a support fixes x and y (pinned), y only (roller_x) or x only (roller_y) |
| `member` | `<name>: <node> -- <node> [section <id>] [material <id>]` | required |  | `chs.*`, `steel.*` | a pin-ended bar between two nodes, one line per member; its options override the defaults |
| `material` | `<registry material id>` | optional |  | `steel.*` | the material of every member that names none; it needs fy, E and density and the section's material family |
| `section` | `<registry section id>` | optional |  | `chs.*` | the circular hollow section of every member that names none |

## Registry

Every id a design can name, then the stocked plate thicknesses a fixed plate thickness is one of,
from `petra registry list`. Shapes are the shipped table's; with
PETRA_SHAPES_XLSX set to the AISC Shapes Database v16.0 workbook, every W and L row in it is an id.
A WT is cut from its W: WT9x25 from W18x50.

Where a steel connection names a grade, a bolt group or an electrode, a common name stands for its
id, in any case, with `Gr` or `Grade` optional, written as one name with `_` between its words or
quoted: `A325` is `bolt_group.120`; `A572_50`, `A572_Gr_50` and `"A572 Gr 50"` are `steel.A572_50`.
A footprint names the id. AISC's thread suffixes are not part of a name: on the bolts line
`-N` is `threads included` and `-X` is `threads excluded`, so A325-N is `bolts bolt_group.120 ... threads included`.
